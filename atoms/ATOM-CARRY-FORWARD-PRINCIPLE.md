# ATOM-CARRY-FORWARD-PRINCIPLE

## Description

Carry Forward / Reject Work — Inspiré de D:\GG-knox\engineering ideas\300-kimi-k3\2.md.

Principe de continuité : le travail valide d'une itération précédente est reporté (carry forward) dans l'itération suivante. Seul le travail invalide ou obsolète est rejeté.

## Règles

1. Tout livrable validé (tests passants, PoL valide) est reporté dans l'itération suivante
2. Un livrable n'est rejeté que s'il est invalide, obsolète ou remplacé par une alternative supérieure
3. Le rejet doit être documenté avec la raison
4. Le carry forward est tracé dans la preuve d'exécution (PoL)
5. Le principe s'applique aux designs, atoms, code, tests, docs
