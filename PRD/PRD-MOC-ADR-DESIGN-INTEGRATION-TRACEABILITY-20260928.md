# PRD-MOC — ADR-Design-Integration Traceability

> **Parent** : PRD-MOC-UNIFIED-DESIGN-CONSUMERS-REGISTRY-20260928.md
> **Périmètre** : garantir que chaque design intégré dans un consumer repo est backed par un ADR accepté, avec traçabilité complète Design → ADR → Consumer → Integration.

---

## 1. Contexte

Les 126 intégrations unified-design sont fonctionnelles, mais la chaîne de traçabilité ADR → Design → Consumer → Integration est incomplète :

| Élément | État | Problème |
|---------|------|----------|
| ADR backing designs | 6/43 acceptés | 37 ADR en `proposed` pour des designs déjà intégrés |
| Cross-references dans PRD-MOC | Partielles | Certains PRD-MOC manquent `related_adr` |
| Traçabilité Design → Consumer | ✅ 126/126 | Chaque design a ses consumers déclarés |
| Traçabilité Consumer → Integration | ✅ 126/126 | Chaque consumer a ses modules d'intégration |
| Traçabilité Integration → ADR | ⚠️ 6/126 | Seuls 6 designs ont un ADR accepté |

### Impact

- Impossible d'auditer pourquoi un design a été choisi (ADR manquant)
- Impossible de vérifier qu'un design implémenté respecte ses invariants (ADR non accepté)
- Risque de drift entre décision architecturale (ADR) et implémentation (Integration)

---

## 2. Mission

Garantir la traçabilité complète ADR → Design → Consumer → Integration pour tous les designs intégrés.

---

## 3. Mécanisme de traçabilité

### 3.1 Format de traçabilité

Chaque PRD-MOC consumer DOIT contenir :

```yaml
---
related_adr: ADR-2026-09-19-SAFE-ACTION-PATTERN.md
related_intent: INTENT-2026-09-19-SAFE-ACTION-PATTERN.md
related_moc: MOC-SAFE-ACTION-PATTERN-20260919.md
parent_doc: PRD-MOC-INTEGRATION-FRAMEWORK-20260928.md
governance:
  adr_status: accepted  # ou proposed
  design_status: active  # ou standard, proposed
  integration_status: functional  # ou stub, missing
---
```

### 3.2 Validation

```bash
# Vérifier la traçabilité ADR → Design → Consumer
python scripts/adr_design_traceability.py --check-all

# Sortie attendue :
# ADR-2026-09-19-SAFE-ACTION-PATTERN: accepted → safe-action-pattern → KIVA-CLI: OK
# ADR-2026-09-21-005-SAFE-ACTION-GATE: proposed → safe-action-gate → KIVA-CLI: WARN
```

### 3.3 Promotion ADR

Tout design intégré avec `integration_status: functional` DOIT avoir son ADR promu de `proposed` à `accepted` dans un délai de 7 jours.

**Exception** : designs en phase expérimentale (POC) peuvent rester `proposed` max 30 jours.
