# ADR-2026-09-21-009 — Pipeline MDU Validation

**Repo** : `gerivdb/unified-design`  
**Strate** : L0-CANON  
**Statut** : proposed  
**Date** : 2026-09-21

---

## Contexte

Le MDU dispose aujourd’hui de plusieurs outils dispersés (`mdu-lint`, `sync-mdu-catalog`, `mdu-integrity-checker`, `dryrun-causal-auditor`), mais il n’existe pas de pipeline qui enchaîne ces étapes dans un workflow reproductible.

## Décision

Ajouter au MDU un pipeline `pipeline-mdu-validation` qui orchestre lint, sync, audit et dryrun en une seule exécution atomique.

## Conséquences

- **MDU** : `meta-design.yaml` mis à jour avec le pipeline
- **Workflow** : `pre-push-validation` intègre le pipeline MDU
- **CI** : Validation MDU reproductible avant tout merge

## Alternatives considérées

| Alternative | Raison rejet |
|-------------|--------------|
| Ne rien ajouter | Validation MDU manuelle et non reproductible |
| Script ad-hoc | Pas d’orchestration ni de traçabilité |
| Pipeline CI externe | Dépend d’un outil hors MDU |
